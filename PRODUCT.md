# Product

## Register

product

## Users

RemNote users who want ChatGPT to read, create, verify, and style notes in an active private knowledge base. They use this panel while connecting ChatGPT, choosing the exact write boundary, selecting a reusable note design, and reviewing sensitive write approvals.

## Product Purpose

RemNote MCP joins a RemNote plugin to an OAuth-protected local or hosted MCP server. Success means the user can understand connection truth, grant the minimum useful write access, choose a reusable design, and let ChatGPT perform scoped, idempotent, read-back-verified work without hidden retries, silent content loss, or false success.

## Brand Personality

Calm, precise, trustworthy. Copy is direct and operational. The interface should feel native to a focused knowledge-work tool, not like a setup wizard or developer console.

## Anti-references

- A first screen dominated by onboarding steps after the plugin is already connected.
- A wall of equal-weight health, copy, registry, and diagnostic buttons.
- Placeholder or mismatched logos, including the former letter-P tab icon.
- Decorative dashboard cards, fake metrics, glass effects, and noisy motion.
- Ambiguous status wording that makes server health look like confirmed RemNote write access.

## Design Principles

1. Show the three daily decisions first: connection truth, writing access, and design template.
2. Reveal diagnostics, pairing internals, tool tiers, and destructive access only when requested.
3. Make every state and action truthful: connection, approval, loading, success, failure, and retry guidance must agree with runtime evidence.
4. Protect the user's note context: exact scope and current style should be understandable without reading bridge terminology.
5. Prefer one clear action over repeated controls; keep reliable workflows familiar and fast.

## Accessibility & Inclusion

Meet WCAG 2.1 AA contrast, preserve visible keyboard focus, use semantic controls and live status announcements, keep touch targets at least 44 by 44 CSS pixels, avoid color-only state communication, support 200% zoom and narrow sidebars without horizontal scrolling, and respect reduced-motion preferences.
